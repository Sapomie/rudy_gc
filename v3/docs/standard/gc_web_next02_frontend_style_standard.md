# gc-web-next02 前端默认样式规范

## 1. 适用范围与强制门槛

- 本规范适用于 `v3/gc-web-next02` 的页面开发、页面重写和视觉调整。
- 默认且唯一的页面视觉基准为当前 `/sc-events` 列表页的最终浏览器渲染效果。
- 基准来源包括 `ScEventsPage.vue` 的实际 DOM、`index.css` 最终生效层、浏览器计算样式、真实截图和元素边界坐标。
- CSS 文件中已经被后续规则覆盖的旧层不得作为实现依据；必须以最终计算结果为准。
- 每开始一个独立页面任务，必须重新完整阅读本规范并检查 `/sc-events` 当前页面。
- 连续处理多个页面时，每个页面都必须独立完成全部实施与验收步骤。
- 禁止依赖记忆、对话摘要、其他页面成品或少数尺寸指标代替完整规范。
- 主题、页面骨架、几何边界、控制栏、表格、链接、状态、动画和验收要求是一个整体；任一适用项未满足时，页面判定为未完成。
- 用户明确指定不同视觉或交互要求时，只允许在该次明确范围内偏离；其余条目继续执行。
- 本规范只约束视觉和交互表现，不得改变业务字段、查询参数、排序、分页、链接和 API 语义。

## 2. 桌面端范围

- 当前项目默认只实施、优化和验证桌面端页面。
- 未经用户明确要求，禁止新增移动端断点、移动端专用布局、表格卡片化、字段隐藏或移动端验证。
- 现有响应式代码默认保留；桌面端任务只处理当前路由实际发生的冲突。
- 桌面端可用空间不足时允许控制栏按 DOM 顺序换行，禁止改成移动端纵向卡片结构。
- 页面整体和表格容器均不得出现横向滚动条。

## 3. 强制页面骨架

### 3.1 页面层级

列表页必须使用与 `/sc-events` 等价的层级：

```html
<PageShell class="...-page-shell">
  <div class="container-fluid ...-page-root next02-sc-pink-theme ...-rewrite">
    <section class="...-hero next02-sc-movie-top-shell">...</section>
    <div class="card ...-panel next02-sc-movie-table-card">
      <div class="card-body">
        <div class="next02-sc-panel-head">
          <form>...</form>
          <div class="...-metrics">...</div>
          <div class="next02-sc-movie-pager">...</div>
        </div>
        <div class="table-responsive">
          <table class="table table-hover align-middle mb-0 ...-table">...</table>
        </div>
      </div>
    </div>
  </div>
</PageShell>
```

- 页面可以使用自己的语义类名，但层级、排列关系和最终几何效果必须一致。
- 筛选、统计、分页和表格必须位于同一个列表面板中。
- 禁止把筛选区和表格拆成两个独立卡片。
- DOM 顺序固定为：筛选区、统计区、分页区、表格。
- 页面标题只在紧凑 Hero 中展示一次；`PageShell` 的重复标题区域必须隐藏。
- Hero 和列表面板必须拥有完全相同的左右外边界。
- 控制栏、底部分隔线和表格外框必须拥有完全相同的左右内边界。

### 3.2 全局导航

- 桌面端左侧导航宽度固定为 `220px`。
- 桌面端顶部导航高度固定为 `64px`。
- 页面不得单独修改导航宽度、高度、品牌、活动状态、标题和快捷导航主题。
- 品牌、左侧导航和顶部快捷导航继续在当前窗口跳转。

## 4. 页面几何基准

### 4.1 页面根容器

- 页面根容器宽度为 `100%`，最大宽度为 `100%`。
- 页面根容器内边距固定为 `18px 16px 36px`。
- 页面根容器使用 `overflow-x: hidden`。
- 页面背景使用顶部粉色光晕和 `#fff3f8 -> #fffafd -> #fceff5` 的纵向渐变。
- 页面内容不得增加无需求的大面积留白。

### 4.2 桌面端边界公式

在展开的 `220px` 侧栏下：

- `PageShell` 内容从主内容区左边向内 `12px` 开始。
- 页面根容器再向内 `16px` 放置 Hero 和列表面板。
- 列表面板边框内的 `card-body` 使用 `18px` 内边距。
- 表格外框边框为 `1px`，实际表格再向内 `1px`。
- 因此所有页面必须按同一层级计算左右边界，禁止用单独的页面 padding 近似对齐。

在本地 Chrome、视口 `1280px`、文档宽度 `1265px`、侧栏展开时，`/sc-events` 的参考坐标为：

| 区域 | Left | Right | Width |
|---|---:|---:|---:|
| 主内容区 | `220px` | `1265px` | `1045px` |
| PageShell / 页面根外框 | `232px` | `1253px` | `1021px` |
| Hero / 列表面板 | `248px` | `1237px` | `989px` |
| 控制栏 / 表格外框 | `267px` | `1218px` | `951px` |
| 实际表格 | `268px` | `1217px` | `949px` |

- 不同桌面宽度下使用相同层级和内边距公式，不机械使用上述绝对坐标。
- 浏览器验收必须比较 `left`、`right`、`width`，三项全部一致才算对齐。
- 只比较行高、字号和颜色不得判定页面与 `/sc-events` 对齐。

## 6. 紧凑 Hero

- Hero 使用 `display: flex`、垂直居中、`gap: 14px`。
- Hero 外边距底部固定为 `10px`。
- Hero 内边距固定为 `9px 14px`。
- Hero 边框为 `1px #eed5e1`，圆角为 `10px`。
- Hero 背景使用白色到浅粉色的 `135deg` 渐变。
- Hero 阴影为低透明粉棕阴影，视觉强度与 `0 12px 30px rgba(132, 52, 88, .085)` 一致。
- Hero 左侧必须有 `3px` 粉色渐变强调线。
- 标识、标题、说明和右侧入口在桌面端保持一行。
- 标识前使用 `18px × 3px` 的粉色短线。
- 标识字号 `10px`、字重 `900`、字间距 `.12em`。
- 标题字号 `18px`、字重 `900`、行高 `1.2`，不得有额外上下外边距。
- 说明字号 `12px`、字重 `700`、行高 `1.35`，空间不足时单行省略。
- 右侧操作区不换行，按钮间距 `8px`。
- Hero 普通按钮最小高度 `30px`、圆角 `6px`、内边距 `5px 10px`、字号 `12px`、字重 `900`。
- 视图切换组使用 `3px` 内边距、`4px` 间距、`8px` 圆角和浅粉背景。
- 当前视图使用浅粉渐变、深粉文字和粉色内描边。
- 页面内容区中进入其他页面的入口必须设置 `target="_blank"` 和 `rel="noopener noreferrer"`。

## 7. 单一列表面板

### 7.1 面板

- 列表面板边框为 `1px #eed5e1`，圆角为 `10px`。
- 面板背景使用 `#fff -> #fffafd` 的纵向渐变。
- 面板阴影与 `0 16px 34px rgba(132, 52, 88, .09)` 一致，并保留轻微白色内高光。
- 面板不得通过 hover 改变尺寸、边界坐标或内容位置。
- `card-body` 内边距固定为 `18px`。

### 7.2 控制栏

- 控制栏使用 `display: flex`、`align-items: center`、`justify-content: space-between`。
- 控制栏允许桌面端按 DOM 顺序换行，列间和行间间距使用 `12px`。
- 控制栏底部外边距固定为 `14px`。
- 控制栏底部内边距固定为 `12px`。
- 控制栏底边固定为 `1px #f1dce6`。
- 筛选区靠左，统计区位于筛选区之后，分页区位于统计区之后。
- 同一行空间足够时：筛选区在左，统计和分页在右。
- 空间不足发生换行时：必须保持 DOM 顺序，禁止通过绝对定位或单独 margin 制造视觉假对齐。

### 7.3 筛选控件

- 筛选表单使用横向 flex，垂直居中，控件间距 `6px`。
- 标签字号 `10px`、字重 `850`、颜色 `#8b6577`。
- 输入框和下拉框高度固定为 `30px`。
- 输入框和下拉框边框为 `1px #eed5e1`，圆角 `6px`。
- 输入框和下拉框内边距为 `3px 8px`，背景为 `#fffafd`。
- 输入框和下拉框字号 `11px`、字重 `780`。
- 日期输入框的 `/sc-events` 基准宽度为 `124px`。
- 每页数量下拉框的 `/sc-events` 基准宽度为 `66px`。
- 其他页面根据字段内容设置宽度，但高度、边框、字号和间距必须一致。
- focus 使用 `#d94f8a` 边框和 `0 0 0 3px rgba(217, 79, 138, .12)` 焦点环。
- 筛选和清空按钮高度 `30px`、圆角 `6px`、水平内边距 `10px`、字号 `11px`、字重 `850`。
- 筛选按钮使用主粉色背景和白色文字。
- 清空按钮使用 `#fff0f6` 背景和 `#9f2f63` 文字。
- 筛选提交必须重置到第一页并保留仍然有效的排序参数。

### 7.4 统计胶囊

- 统计区使用横向 flex，间距 `6px`，不得换行。
- 每个统计胶囊高度固定为 `30px`。
- 胶囊边框为 `1px rgba(217, 79, 138, .2)`，圆角 `999px`。
- 胶囊水平内边距为 `9px`，背景为 `#fff0f6`。
- 标签字号 `10px`、字重 `800`、颜色 `#8b6577`。
- 数值字号 `12px`、字重 `900`、颜色 `#9f2f63`，使用 `tabular-nums`。
- 只展示必要统计，禁止重复摘要卡。

### 7.5 分页

- 分页外框使用白色背景、`1px #eed5e1` 边框、`7px` 圆角。
- 分页外框高度由 `30px` 页码和上下 `1px` 边框组成，最终为 `32px`。
- 分页外框使用 `0 6px 16px rgba(132, 52, 88, .065)` 阴影。
- 页码高度固定为 `30px`，最小宽度 `30px`，水平内边距 `8px`。
- 页码之间只保留右侧 `1px #f1dce6` 分隔线，最后一个页码取消右边线。
- 页码字号 `11px`、字重 `850`。
- 默认页码使用白色背景和 `#82576b` 文字。
- 当前页使用 `#d94f8a` 背景和白色文字。
- disabled 使用 `#fff5fa` 背景和 `#b593a3` 文字。
- hover 使用 `#fff0f6` 背景和 `#d94f8a` 文字。
- 分页链接必须保留全部有效筛选、排序和每页数量参数。
- 分页属于当前页面操作，继续在当前窗口执行。

## 8. 表格严格基准

### 8.1 表格外框

- 表格外框必须与控制栏拥有相同的 `left`、`right` 和 `width`。
- 表格外框宽度 `100%`，边框为 `1px #eed5e1`，圆角为 `7px`。
- 表格外框使用白色背景和 `0 10px 24px rgba(132, 52, 88, .055)` 阴影。
- 表格外框必须使用 `overflow: hidden`，禁止横向滚动条。

### 8.2 表格基础

- 表格必须保留 `table table-hover align-middle mb-0` 基础类，并添加页面专属表格类。
- 页面专属表格类必须显式覆盖最终视觉，禁止依赖 Bootstrap 默认外观完成交付。
- 表格宽度 `100%`、最小宽度 `0`、最大宽度 `100%`。
- 表格使用 `table-layout: fixed`、`border-collapse: separate`、`border-spacing: 0`。
- 表格背景为白色，文字颜色为 `#4b2939`，字号为 `13px`。
- 表头和数据单元格全部默认水平居中、垂直居中。
- 禁止页面自行改成默认左对齐。

### 8.3 单元格

- 表头高度固定为 `30px`。
- 数据行和数据单元格高度固定为 `28px`。
- 表头和数据单元格内边距固定为 `1px 10px 2px`。
- 表头和数据单元格右边线、底边线统一为 `1px #f1dce6`。
- 最后一列取消右边线，最后一行取消底边线。
- 所有单元格使用单行显示、`overflow: hidden` 和 `text-overflow: ellipsis`。
- 数据文字字重默认 `680`，行高 `1.15`。
- 数字列字重 `800`，使用 `tabular-nums`。
- 主要数字使用 `#9f2f63` 和字重 `900`。
- hover、focus、active 均不得改变行高、列宽、内边距或表格位置。

### 8.4 表头

- 表头使用 sticky，`top: 0`、`z-index: 2`。
- 表头背景固定为 `#fcecf4`，文字颜色 `#6d3b53`，字号 `13px`、字重 `850`。
- 表头底部使用 `1px #f1dce6` 稳定分隔线。
- 首列表头必须有 `3px #d94f8a` 左侧内强调线。
- 可排序表头使用指针光标。
- 可排序表头 hover 背景为 `#fde8f2`、文字为 `#9f2f63`。
- 可排序表头 hover 底部增加 `2px #d94f8a` 内强调线，同时保留原底部分隔线。
- 排序链接字号 `13px`、字重 `850`，不使用下划线和文字阴影。
- 当前排序只改变为深粉色，不增加持续显示的底部横线。

### 8.5 列宽

- 每张表必须根据自身真实字段内容重新规划列宽。
- 所有列宽必须通过 `colgroup` 明确声明，宽度总和必须为 `100%`。
- 禁止自动等分列宽。
- 禁止机械复制 `/sc-events` 的列宽到字段不同的页面。
- `/sc-events` 当前列宽只作为其自身固定基准：

| 列 | 宽度 |
|---|---:|
| 时间 | `11%` |
| 总片数 | `3.5%` |
| 有 SC | `3.5%` |
| Come 片 | `15%` |
| Cooldown | `6%` |
| 时长(分钟) | `5%` |
| 种类 | `7%` |
| 演员 | `18%` |
| Vessel | `6%` |
| FG | `25%` |

- 时间、日期和短固定格式字段必须完整显示。
- 长标题、长名称、Hash 和备注字段可以单行省略，但必须通过 `title` 或等价方式保留完整内容。
- 禁止使用 `max-width: 0`、不稳定 `calc()` 或像素与百分比混合列宽。

### 8.6 日期与时间

- `/sc-events` 时间结构使用同一行的“日期 + 较小时间”两级文本。
- 时间容器使用 inline-flex、基线对齐、`gap: 5px`、不换行。
- 日期字号 `13px`、字重 `900`、颜色 `#573144`。
- 小时字号 `11px`、字重 `780`、颜色 `#956f81`。
- 时间不得使用胶囊背景、徽章边框或独立块级布局。
- 其他页面包含秒时可以使用完整时间文本，但必须保持同一行、无胶囊、无背景并完整显示。

### 8.7 分组行

- 时间列表必须根据页面实际时间粒度生成分组类，不得只用统一白色背景。
- `/sc-events` 按月份分组，背景循环使用：
  - 第一组：`#fff8fb`
  - 第二组：`#fff1f6`
  - 第三组：`#fcecf4`
- 新分组第一行的首列必须增加 `4px #d94f8a` 左侧内强调线。
- 首条数据属于当前分组但不额外标记为“新分组开始”；后续分组变化时增加开始标记。
- 行分组背景必须覆盖整行全部单元格。

### 8.8 行与链接 hover

- 数据行 hover 时，全部单元格背景统一改为 `#fde8f2`。
- 数据行 hover 后行高仍必须为 `28px`。
- 数据行 hover 的首列保留 `3px #d94f8a` 左侧内强调线。
- 页面入口链接默认颜色为 `#9f2f63`、字重 `850`。
- 链接 hover 颜色为 `#d94f8a`，显示下划线，`text-underline-offset: 2px`。
- 链接 hover 禁止边框、背景、阴影和位移。
- 页面内容区中进入其他页面的链接必须设置 `target="_blank"` 和 `rel="noopener noreferrer"`。
- 当前页面的筛选、排序、分页和清空继续在当前窗口执行。

### 8.9 操作列和空状态

- 表格内操作按钮必须保持紧凑，并保证整行高度仍为 `28px`。
- 操作按钮不得撑大单元格或迫使内容换行。
- 空状态位于表格 `tbody` 内，`colspan` 必须覆盖全部列。
- 空状态不得破坏表格外框、表头或列结构。

## 9. 动画与交互状态

- 页面进入使用轻量淡入，基准时长 `280ms`。
- Hero 和列表面板允许小幅上浮进入，禁止大距离位移和强缩放。
- 普通 hover 动画控制在 `140ms–180ms`。
- 控件必须具备清晰的 hover、active、focus 和 disabled 状态。
- focus-visible 使用粉色焦点反馈，不得导致布局移动。
- 必须提供 `prefers-reduced-motion: reduce`，关闭非必要动画和位移。
- 面板 hover 只能增强边框或阴影，不得改变几何尺寸。

## 10. 冲突样式清理

- 修改前必须搜索当前路由、页面根类、面板类、控制栏类和表格类的全部样式声明。
- 必须区分基础层、已覆盖旧层和最终生效层。
- 当前路由存在旧主题或旧表格规则时，必须删除或改写冲突声明。
- 禁止在文件末尾追加更高优先级规则来掩盖冲突。
- 禁止保留两套同时生效的主题或表格外观。
- 共享基础规则影响当前页面时，必须精确清理当前路由的冲突，不得破坏其他页面。
- 最终页面只能由一套明确的页面专属规则和必要的共享基线共同控制。

## 11. 严格验收清单

### 11.1 修改前

- 完整阅读本规范。
- 打开 `/sc-events` 并保存桌面端基准截图。
- 读取目标页面真实字段、真实数据长度和全部业务操作。
- 搜索目标路由全部现有 CSS，列出冲突规则。
- 画出目标页面 Hero、列表面板、控制栏、表格的层级关系。
- 规划列宽并确认总和为 `100%`。

### 11.2 修改后：结构

- Hero 和列表面板左右边界完全一致。
- 筛选、统计、分页和表格位于同一个列表面板。
- 控制栏和表格外框左右边界完全一致。
- 表格实际边界位于外框边界内 `1px`。
- 页面没有重复标题、重复说明、重复统计或装饰摘要。

### 11.3 修改后：计算样式

逐项读取并记录：

- 导航宽度 `220px`。
- 顶栏高度 `64px`。
- 页面根内边距 `18px 16px 36px`。
- Hero 内边距 `9px 14px`、底部间距 `10px`。
- 面板 `card-body` 内边距 `18px`。
- 控制栏 `gap: 12px`、`margin-bottom: 14px`、`padding-bottom: 12px`。
- 表格外框边框 `1px`、圆角 `7px`、`overflow-x: hidden`。
- 表头 `30px`、数据行 `28px`。
- 单元格字号 `13px`、内边距 `1px 10px 2px`。
- 单元格水平和垂直居中。
- 横纵网格线颜色 `#f1dce6`。
- 列宽总和 `100%`。
- 页面和表格均无横向溢出。

### 11.4 修改后：边界坐标

- 同一桌面视口分别读取 `/sc-events` 和目标页面的 `getBoundingClientRect()`。
- 必须对比 Hero、列表面板、控制栏、表格外框和实际表格的 `left`、`right`、`width`。
- 对应区域坐标必须一致；存在差异时页面判定为未对齐。
- 禁止用“视觉接近”或“内部尺寸相同”替代边界坐标一致。

### 11.5 修改后：真实视觉和交互

- 使用真实数据截图逐项对照 `/sc-events`。
- 检查表头背景、首列强调线、横纵网格、分组背景和新分组首行强调线。
- 实际 hover 可排序表头，确认背景、文字和底部 `2px` 强调线。
- 实际 hover 数据行，确认整行背景、首列强调线和 `28px` 行高。
- 实际 hover 页面入口链接，确认颜色和下划线且无位移。
- 检查筛选、排序、分页、清空及有效参数保留。
- 检查跨页面入口的新窗口属性。
- 只打开弹窗进行验证，禁止提交会改变业务数据的操作。
- 检查浏览器控制台错误。

### 11.6 工程验证和完成门槛

- 执行 `git diff --check`。
- 执行 `make check-web-next02`。
- 执行生产构建。
- 确认没有新增移动端断点或移动端结构。
- 以上全部适用项通过后，才允许在进度文档写入“交互检查通过”。
- 任一项未通过时，必须明确标记为待检查，禁止宣称完成。

## 12. 禁止项

- 禁止只对齐颜色、字号、行高或单元格内边距。
- 禁止忽略表格和面板的左右边界。
- 禁止默认左对齐表格内容。
- 禁止拆分筛选卡片和表格卡片。
- 禁止省略月份或时间分组背景。
- 禁止省略表头首列和新分组首行的粉色强调线。
- 禁止使用 Bootstrap 默认外观代替最终页面样式。
- 禁止通过高优先级后置 CSS 隐藏旧冲突。
- 禁止新增无需求摘要、装饰性 KPI 或重复统计。
- 禁止改变已有字段、按钮、筛选参数、排序、分页、链接和 API 语义。
- 禁止在未完成截图、计算样式、边界坐标和交互 hover 检查时宣称严格对齐。

## 13. 规则优先级

- 用户当前明确要求高于本文档默认规范。
- 用户没有提出特殊要求时，本规范是 `gc-web-next02` 前端视觉和列表页面的唯一默认基准。
- 页面业务结构、字段和交互语义继续以当前项目既有实现和用户要求为准。
