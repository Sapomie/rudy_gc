# 通用代码库工作流

## 开始前

- 先读取当前仓库的项目规则文件，例如 `AGENTS.md`、README、CONTRIBUTING 或团队约定文档。
- 用户问实现、差异、原因、调用链时，必须当次检索并读取相关文件后再回答。
- 不用历史记忆替代当前代码状态。
- 优先使用 `rg` 和 `rg --files` 检索。

## 改动前

- 先找同类实现，确认项目已有风格。
- 后端改动要查看同类 handler、service、model/repo、DTO、错误处理和缓存路径。
- 前端改动要查看同类页面、模板、JS/CSS、导航入口和参考组件。
- 数据库改动要查看表结构定义、生成 model、自定义查询、迁移和缓存失效方式。

## 实现中

- 保持分层一致，不在不该写 SQL 的层写 SQL。
- 不复用语义不同的 DTO；不同业务含义应拆成不同结构。
- 新增接口、方法或字段后，全局检索旧路径，清理未使用代码。
- 写路径要沿用项目统一 Update/Delete/Insert 封装，避免绕开缓存失效。
- 范围更新或删除默认先查 ID，再走统一更新/删除路径；除非项目明确允许批量直写。

## 收尾

- 改动后再次全局检索相关关键字，确认没有旧链接、旧接口、旧字段或旧语义残留。
- 运行必要的格式化和包级测试。
- 对风险较高的查询做执行计划或等价索引命中检查。
- 最终说明验证结果和未验证项。
