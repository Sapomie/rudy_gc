# 领域语义与链接规则

## ID 语义

业务系统里常见多种 ID，必须严格区分：

- 展示 ID：用户能看懂、能出现在页面上的编号或名称。
- 内部 ID：数据库内部稳定关联键。
- 外部 ID：第三方系统的标识。
- 路由参数：页面 URL 中暴露的参数。
- 关联键：表之间 join 或外键语义使用的字段。

不要因为字段值看起来相似就混用。改动前要确认每个字段的来源、用途和是否可展示。

## 链接生成

- 页面跳转链接应由后端 ViewModel 明确生成，例如 `Href`、`DetailHref`、`MovieHref`。
- 模板应直接渲染链接字段，不临时拼复杂业务路径。
- 如果同一实体既需要展示又需要内部关联，ViewModel 应拆分字段，例如：
  - `DisplayName`
  - `InternalID`
  - `ExternalID`
  - `DetailHref`

## 查询参数

- 查询参数的语义要稳定，不能同一个参数在不同页面中混用不同含义。
- 多值参数要明确分隔符、去重规则、空值处理和结果语义。
- 数值参数必须区分“未传”和“传入 0”；`0` 可能是合法业务值。

## 变更自检

- 全局检索路由拼接。
- 全局检索内部 ID 是否被用于用户可见链接。
- 检查模板是否仍在拼接复杂链接。
- 检查 API、页面、service、model 的字段语义是否一致。
