# 前端改动工作流

## 开始前

- 先找项目已有参考页面、设计系统、模板片段、组件样式和页面专用 JS/CSS。
- 如果项目有 `z_reference`、storybook、design system 或示例页面，优先阅读。
- 不要在已有视觉体系清晰时自创新结构。

## 实现规则

- 复用已有布局、表单、按钮、表格、分页、空态、弹框和提示样式。
- 新增页面应补齐路由、导航入口、筛选区、排序区、分页区、表格区、空态和操作列，除非需求明确删减。
- 大段 CSS/JS 不要内联在模板里，应拆到项目约定的静态文件目录。
- 默认入口链接不要携带默认查询参数，默认值由 handler/service 兜底。
- 模板只渲染后端准备好的业务链接，不临时拼复杂业务路径。

## 自检

- 路由可访问。
- 导航可进入。
- 筛选、排序、分页参数能保留。
- 按钮、弹框、确认动作、错误提示可用。
- 页面主区域和原有布局没有明显错位。
- 没有引入与项目风格冲突的全局样式。
