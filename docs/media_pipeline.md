# Media 流程规划（w_media）

本文档定义新版本媒体处理的两条流程：`ingest_new` 与 `reconcile_full`。

## 目标

- 新增文件走一次性处理：识别、补信息、重命名、移动、入库。
- 全量扫描与一致性修复独立成另一条链路，避免影响新增吞吐。
- 命名规则简化，但保留可回溯的业务信息。

## 流程一：ingest_new（新增入库）

适用场景：有新文件进入“待处理目录”。

### 输入

- 新增媒体文件路径（单个或批量）
- 可选来源信息（如 `source_torrent_hash`）

### 处理顺序（一次完成）

1. 预检文件可读性与扩展名。
2. 解析文件名并提取基础特征（沿用旧逻辑可识别的信息）：
   - 是否自制
   - 是否有字幕
   - 是否有 mask
   - 其他已有可解析标记
3. 识别番号核心信息（前缀、序号等）并拉取影片补充信息。
4. 生成新文件名（简化命名）：
   - 前缀字母做 Base36 数字化（A=10...Z=35）
   - 保留必要业务段，去掉历史冗余段
5. 根据目录规则计算目标目录并移动文件。
6. 写入/更新 `w_media` 记录（含最新路径、文件信息、解析标记、来源 hash）。
7. 记录处理结果（成功/失败、失败原因），支持重试。

### 输出

- 文件已在目标目录落位（命名完成）
- `w_media` 中有可查询的最新记录
- 任务日志可审计

## 流程二：reconcile_full（全量对账）

适用场景：定时巡检、历史数据修复、目录结构调整后校准。

### 输入

- 约定根目录（全量扫描范围）

### 处理顺序

1. 扫描磁盘现有文件清单。
2. 与 `w_media` 做路径与存在性对账：
   - 文件在库中但磁盘不存在：标记删除/失效状态
   - 磁盘存在但库中不存在：补建记录（按 ingest_new 规则补元信息）
   - 路径不一致：修正路径与文件信息
3. 可选修复：补齐缺失元数据、纠正异常命名。
4. 产出对账报告（新增、修正、失效数量）。

### 输出

- `w_media` 与磁盘状态一致
- 异常有报告可追踪

## 两条流程的边界

- `ingest_new`：面向“新进文件”，强调实时、快、一步到位。
- `reconcile_full`：面向“全局一致性”，强调兜底修复与数据可信。
- 两者共享同一套命名与解析规则，避免结果不一致。

## 命名规则建议（简化版）

- 文件名由“稳定标识段 + 必要业务标签段”组成，避免过长。
- 将前缀字母转换为 Base36 数字段，用于弱化原始字母可见性。
- 保留可直接用于筛选的标签（如自制/字幕/mask），其余展示信息放数据库字段，不堆入文件名。

## 状态建议

`w_media` 可使用统一处理状态，便于任务重试与可观测：

- `pending`：待处理
- `processing`：处理中
- `ready`：处理完成
- `failed`：处理失败
- `missing`：对账发现文件缺失

## 实施建议

1. 先实现 `ingest_new` 闭环，确保“新增即落位可用”。
2. 再接入 `reconcile_full` 定时任务，负责全量兜底。
3. 两条流程共用同一套解析器与命名器，避免分叉。
