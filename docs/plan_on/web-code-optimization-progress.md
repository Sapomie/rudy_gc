## 2. 记录规则

本文件记录优化方案的实际实施过程，方案内容和目标边界继续以 `web-code-optimization-plan.md` 为准。

每次实施后需要同步记录：

1. 当前阶段状态。
2. 实际修改文件。
3. 实际完成内容。
4. 执行的检查命令及结果。
5. 实际验证的页面、接口和交互。
6. 未验证项及原因。
7. 新发现的历史问题和风险。
8. 下一步依赖。

状态定义：

- `待开始`：阶段尚未执行代码修改。
- `进行中`：阶段已经开始，仍有方案内工作未完成。
- `已完成`：阶段方案内工作和要求的验证均已完成。
- `受阻`：阶段存在明确阻塞条件，当前无法继续。

记录要求：

- 只记录实际完成和实际验证的内容。
- 未执行的检查统一标记为“未验证”。
- 历史问题与本次修改引入的问题分别记录。
- 实际文件范围与方案不一致时，记录差异和原因。
- 不将后续阶段内容混入当前阶段实施。
- 不修改现有业务上限、默认截断和业务语义，除非任务明确要求。
